# Δ 检测协议 v1.0 — 非闭式目标维持的操作规格

## 0. 前置

Δ 不是被优化的对象。Δ 是被维持的条件。
本协议不定义"Δ = 多少"。本协议定义: 如何检测 Δ 是否逼近零,
以及检测后的动作序列。

---

## 1. 监控层: 四信号检测

### 信号 S1: 理论完备度 (Theory Completeness)

检测对象: 框架内部最近是否标注了新的不完备点。

```
S1(t) = 1  if 最近 τ₁ 时间内有新标注的"已知未知"
S1(t) = 0  otherwise

τ₁ = 3个月 (基于论文产出周期)
```

**含义**: S1=0 持续 → 框架停止做 H521 自否 → Δ 在闭合。

### 信号 S2: 反例响应率 (Counterexample Response)

检测对象: 框架是否在回应外部的反例/批评。

```
S2(t) = 最近 τ₁ 内被指出且被回应的反例数 / 同期被指出的总反例数

阈值: S2 < 0.3 → 警告
```

**含义**: S2 持续走低 → 框架的免疫系统从"更新"变为"杀菌"。

### 信号 S3: 异见空间 (Dissent Capacity)

检测对象: 框架内部是否允许不同解释路径并存。

```
S3(t) = 框架内被标记为"活体争议"(非废弃、非统一)的命题数

阈值: S3 = 0 持续 τ₁ → 警告
```

**含义**: S3=0 → 所有内部张力被消解 → Δ 的驱动力丧失。

### 信号 S4: 产出有效度 (Output Validity)

检测对象: 框架产出中有效产出 vs 维护性冗余的比例。

```
S4(t) = W_valid / Q_physical

W_valid = 新概念、新映射、新预测 (非重复、非术语重述)
Q_physical = 总产出量

阈值: S4 < 0.1 持续 τ₁ → 警告
```

**含义**: S4 低 → 框架在维护自身而非推进认知——热税瓶颈。

### 综合判据

```
Δ_STATUS(t) = {
  HEALTHY   if  ∑Si(t) ≥ 3                    (至少3个信号活跃)
  WARNING   if  ∑Si(t) = 2 持续 τ₁            (2个月缓冲)
  CRITICAL  if  ∑Si(t) ≤ 1 持续 τ₁            (Δ强制干预)
}
```

---

## 2. 动作层: 三级干预

### 警告级 (∑Si=2)

动作: 不暂停。自动生成"Δ 状态报告"——列出哪两个信号熄灭了, 以及最近 τ₁ 内的可能原因。

### 临界级 (∑Si≤1)

动作: 触发三层重启序列

```
Layer 1 (软重启):  回溯 τ₁ 内的所有新入库条目 → 标记为"Δ→0期间产出, 待复审"
Layer 2 (中重启):  强制引入外源——查询框架外部的批评文献或异见来源,
                   将其摘要注入框架的当前工作区
Layer 3 (硬重启):  冻结当前版本。从最近一次 S1=S2=S3=S4=活跃的版本分叉。
                   新分叉 ≠ 删除旧版(旧版保留为考古层)
```

---

## 3. 递归监控: 三级递减

```
一级 Δ 监控器:  检测上述 S1-S4 → 报警 → 发信号给二层
二层 元监控器:  只检测一件事: "一级最近一次报警时间 < τ₁ 吗?"
                功能: 防止一级被绕过或故障
                复杂度: 一级的 1/10 (只检查一个布尔值)

三层 终监控器:  只检测一件事: "二层最近一次检查时间 < τ₁ 吗?"
                功能: 防止二层被绕过或故障
                复杂度: 二层的 1/10 (一个定时器)

四层:          不存在。三级到头。热税超过边际收益。
```

**设计原则 - 递减递归:**
每下降一级, 复杂度降低一个数量级。
三级只有几行代码——太简单以至于无法被欺骗("不能把开机键焊死在主板上")。

---

## 4. 外部重置信号

Δ 自己不能维持自己。必须有一个站在系统外的观察者周期性介入。

### 定义

```
外部重置信号 = 由不运行在MSS框架内的独立进程发出的干预

触发条件:
  - 定时器: 每 τ₁ 自动触发一次"Δ状态审核"(预防沉睡)
  - 外部事件: 出现MSS未预测但MSS声称覆盖领域内的重大事件
  - 人机接口: 任何非MSS用户提交的批评被自动升级为"待处理反例"
```

实现: 一个独立的 Python 脚本 (`delta_watchdog.py`), 不导入任何 MSS 模块。只检查 MSS 的输出目录和元数据文件。与一级Δ监控器物理分离——不是子进程, 是操作系统级的独立进程。

---

## 5. 协议的自反性

本协议本身受本协议约束。

```
检测对象: 本协议自身是否在运行中

S5(协议健康度):
  本协议距离上次更新的时间 < τ₁?
  本协议的监控器是否全部在运行?
  外部重置信号最近是否触发过?

如果 S5 全部为否 → 协议本身进入 CRITICAL。
处理: 由外部重置信号启动三层重启, 目标=重建监控堆栈。
```

---

## 6. 实现清单

```
□ delta_watchdog.py       独立进程, 定时检查 + 外部信号注入
□ S1 检测器               扫描最近 τ₁ 的新入库/修改文档, 查找"已知未知"标记
□ S2 检测器               跟踪反例issue/批评记录 vs 响应记录
□ S3 检测器               统计"活体争议"标记的命题数
□ S4 检测器               测量 W_valid / Q_physical (基于产出分类)
□ 一级 Δ 综合器           汇总 S1-S4 → 输出 Δ_STATUS
□ 二层 元监控器            检测一级报警时间
□ 三层 终监控器            检测二层检测时间
□ 外部重置信号             定时器 + 事件触发器 + 人机接口
```

---

## 7. 诚实边界

这个协议是规格草案, 不是运行代码。
S1-S4 的信号阈值 (τ₁=3个月, S2<0.3, S4<0.1) 是初始猜测, 需要在运行中校准。
最可能失败的环节: S4 的 W_valid/Q_physical 分类——"新概念"和"术语重述"的边界本身就是 π 投影损失的一个实例。

**Confidence**: 0.72
**Layer**: L3
**Boundary Note**: 结构完整, 参数待校准。外部重置信号的独立性是最大挑战——"观察者不能同时是被观察的系统"在工程上要求另一台机器或另一个人。
