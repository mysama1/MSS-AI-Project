# 蜕壳协议 v1.0 — Closure Detection as Iteration Trigger

## 修正

H521 原表述: "MSS必须保持结构性不完备"
修正后: "MSS的每一次完备都是暂时的。闭合度检测的意义不是防止闭合, 
         而是在闭合超过阈值时触发蜕壳。"

## 闭合 vs 僵化

```
闭合       = 当前版本自洽 → 正常, 是迭代的终点
蜕壳       = 闭合后产生新裂缝 → 打开 → 下一版
僵化       = 闭合后拒绝产生裂缝 → 护城河锁定 → 死亡

MSS: 闭合 → 蜕壳 → 闭合 → 蜕壳 → ... 
K3: 闭合 → 加固 → 再加固 → 再加固 → 化石
```

## 蜕壳触发条件

基于 S1-S4 + G1-G3 的综合:

```
Σ_close = w1×S1 + w2×S2 + w3×S3 + w4×S4 + wG×G1

阈值:
  Σ_close < 0.4    → 太开放 (还没长好, 当前壳未硬化)
  0.4 ≤ Σ_close < 0.7  → 健康
  Σ_close ≥ 0.7    → 壳开始太紧 → 启动下一版规划
  Σ_close ≥ 0.85   → 紧急 → 强制版本分叉
```

## 蜕壳操作

不是推翻。是分叉:

```
v17.x (当前壳) → 继续维护, 处理已知反例
           ↓
v18.0 (新壳)  → 吸收 v17.x 无法吸收的新现象
           从 v17.x 的"诚实边界"区块里提取未解决问题列表
           新壳不必比旧壳大 (体量不是目标)
           新壳必须能解释旧壳无法解释的至少一个问题
```
